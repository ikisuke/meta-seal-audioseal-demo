# Meta Seal / AudioSeal demo

This repository is a small hands-on trial of Meta Seal's AudioSeal model.

Meta Seal is Meta's umbrella page for open-source invisible watermarking across
audio, image/video, text, generation-time watermarking, dataset watermarking,
and watermark security. I used AudioSeal here because it is quick to run on a
Windows CPU machine and demonstrates the core product pattern clearly:

1. Create or receive generated audio.
2. Embed an invisible watermark after generation.
3. Store or distribute the watermarked media.
4. Later, run the detector to check whether the audio came from that pipeline
   and optionally recover a 16-bit identifier.

## What this demo does

The script:

1. Generates a deterministic five-second speech-like waveform.
2. Loads `audioseal_wm_16bits` and `audioseal_detector_16bits`.
3. Embeds a fixed 16-bit message.
4. Detects watermark probability for:
   - clean audio,
   - watermarked audio,
   - watermarked audio with 30 dB noise,
   - watermarked audio resampled from 16 kHz to 8 kHz and back,
   - a three-second crop from the middle.
5. Writes `.wav` files and `results.json` into `outputs/`.

## Run

```powershell
uv sync
uv run audioseal-demo
```

On Windows CPU environments this demo sets `NO_TORCH_COMPILE=1` before importing
AudioSeal. Without that, PyTorch may try to compile kernels and fail if the MSVC
`cl` compiler is not installed.

## Result from my run

The generated `outputs/results.json` from my local run showed:

- clean score: about `0.16`
- watermarked score: `1.0`
- decoded message: matched all 16 bits
- watermark SNR: about `46.6 dB`

Those numbers are for a synthetic toy waveform, not a benchmark. For a real
deployment, test on your own generated speech, codecs, upload pipeline, clipping,
normalization, and moderation/transcoding steps.

## Where I would use it

AudioSeal fits best at the boundary where generated audio leaves your system:

- TTS or voice-cloning products: watermark the final PCM/WAV before export.
- Voice agents: watermark streamed or recorded agent replies for later provenance checks.
- UGC platforms: scan uploaded audio to identify media generated by your own tools.
- Internal model QA: tag outputs by model version, provider, experiment, or tenant using the 16-bit message.

It is not a replacement for visible labels, consent flows, cryptographic signing,
or content credentials. I would treat it as one signal in a provenance stack.
